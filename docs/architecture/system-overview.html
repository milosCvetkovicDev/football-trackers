DIY real-time youth-football tracking · two pipelines, one wire-contract discipline

A real-time GPS tracker and an
offline camera/CV analysis system

Each player wears an ESP32 + u-blox NEO-M8N that streams position at 10 Hz over Wi-Fi → Mosquitto MQTT → a single-process Bun + Elysia server that server-stamps, persists, and fans out to a live coach view. A separate, fully offline Python CV pipeline (vision/) turns recorded match video into player/ball tracks, a top-down radar, and stats. Private hobby project; children's location & imagery is the load-bearing constraint throughout.

Pipeline 1 — real-time GPS

The wearable → broker → server → coach loop

One pipeline, one frozen wire contract binding firmware → broker → server. Everything is instrumented; nothing the device says about time or identity is trusted — the server re-derives both.

firmware/

① Wearable — ESP32 + NEO-M8N

A WEMOS LOLIN32 Lite + u-blox NEO-M8N. The M8N ships at 9600 baud / 1 Hz / NMEA; the firmware talks UBX to reconfigure it on boot.

  • GPS bring-up (gpsBegin): raise serial to 115200, switch to UBX-only output, set 10 Hz, enable autoPVT, persist to module flash — with a 9600 fallback.
  • Publish loop: on each fresh PVT, build the JSON packet and mqtt.publish(). Unit conversions happen here: lat/lon ÷1e7 (7 dp), speed mm/s→m/s, heading ÷1e5, pdop ÷100.
  • Field resilience (Phase 4): Wi-Fi/MQTT down → position fixes append to a two-file 2×128 KB LittleFS backlog (drop-oldest when full). Replay is paced (~30 msg/s) from an NVS cursor (checkpoint every 20 records) — a crash mid-replay re-sends at most one window, deduped server-side by sq; records keep their GPS-UTC time (gts), so a replayed outage spans its real duration.
  • Status heartbeat (~5 s): battery / RSSI / heap / backlog / fix to .../status. Best-effort, never backlogged — health only matters live.
firmware/src/main.cppplatformio.ini
secrets · NVS

One image, zero secrets in source

The same firmware binary flashes onto every device. Secrets live in ESP32 NVS, set once.

  • Wi-Fi PSK + per-device MQTT username (= PLAYER_ID) + password are provisioned via a serial enroll console or a phone captive-portal Wi-Fi setup — never compiled in.
  • Broker host is dynamic: NVS MQTT_HOST may be a name.local mDNS address resolved at connect time (ADR-0022).
  • MQTT username == PLAYER_ID so the broker's per-device topic ACL is enforced server-side (ADR-0007).

Decisions: ADR-0014 (NVS provisioning), ADR-0022 (dynamic host + mDNS + portal), ADR-0007 (per-device identity).

The binding contract

One packet shape, hover a key to read it

The terse JSON the firmware builds is RawTelemetry in server/src/types.ts. The server subscribes with the MQTT + wildcard and recovers sessionId/playerId by re-matching the concrete topic with TOPIC_RE. Change one side and you change both.

{ "id": "trk-01-AB12", "pl": "01", "ts": 184523, "lat": 44.8125083, "lon": 20.4610976, "spd": 5.42, "hdg": 271.3, "fix": 3, "sats": 11, "pdop": 1.4 }

Enriched server-side into Telemetry = RawTelemetry + sessionId, playerId, serverTs.

Server — ingest, fan-out, persist

Ingest is a funnel, and the server owns the truth

server/src/ingest.ts: MQTT QoS0 → JSON-parse → drop packets with no real fix → enrich into Telemetry → insertTelemetry() → publish(sessionId, t). Every step is timed and every drop is counted by reason.

The drop funnel

MQTT QoS0 received
received_total
drop — fix < 2 (no GNSS lock)
dropped: no_fix
drop — non-numeric lat
dropped: bad_lat
enriched + persisted + fanned out
published_total

Drops are counted by reason in ft_telemetry_dropped_total{reason=…} so a field of stale dots is explainable, not mysterious. Indoors, every fix correctly drops no_fix — confirmed at the first real bring-up.

the invariant

Three timestamps, by design (Phase 4)

A system-wide rule, not an accident:

  • ts = the device clock (millis()). Ordering only, explicitly NOT authoritative — clocks drift, devices reboot.
  • serverTs = Date.now() stamped at ingest. The source of truth for everything downstream — storage, replay, analytics.

The split lives across main.cpp, types.ts (RawTelemetry vs Telemetry), and ingest.ts. Preserve it.

Persistence

server/src/db.ts — bun:sqlite, WAL mode, one prepared insert per packet (no batching needed at ~100 msg/s). This is the "local SQLite" baseline; swap this module for a TimescaleDB writer later without touching ingest.ts (ADR-0011).

Transport & observability

Native WS rooms, a zero-dep Prometheus registry, off-loop reads

Fan-out uses Bun's native WS pub/sub — not socket.io — so the coach view uses a plain WebSocket. One room per session means a tablet only ever sees its own match.

server/src/server.ts

Live fan-out

  • Elysia .ws('/live'); connect to /live?sessionId=<id>, the open handler does ws.subscribe('session:'+id).
  • Frames are JSON envelopes: {event:'telemetry', data:Telemetry} and {event:'status', data:DeviceHealth}.
  • server.publish('session:'+id, …) wired from the ingest publish callback.
auth · ADR-0015/16

Same-origin auth

  • argon2id via Bun.password (no auth dep).
  • HttpOnly __Host-/ft_session cookie on the same-origin WS upgrade — the bundled token was killed.
  • Principal-bound /live authz; rejects counted in ft_ws_rejected{reason}.
scanLoad.ts

Off-loop reads

  • GET /sessions/:id/history (replay) & /events (Track A) read off the live loop via keyset paging + yields.
  • Both share one global scan slot — OFFLOOP_MAX_INFLIGHT — so concurrent scans can't gang up on live ingest.
  • Per-principal rate-limit + audit log + Cache-Control: no-store.

The coach view — Vite + React + canvas

A plain WebSocket, a useRef map, a requestAnimationFrame canvas

No socket.io. Positions land in a useRef Map (not React state — the render loop reads it directly), drawn on a DPR-crisp <canvas> at ~30 fps with a GPS→pitch homography. A Live ⟷ Review toggle swaps the data source under one renderer.

Transport & store

  • useLiveTelemetry.ts — plain WebSocket to /live?sessionId; positions in a useRef Map; distance accumulator.
  • ws/validate.ts — every inbound envelope is schema-checked before it touches the store.
  • Strict CSP, connect-src 'self', same-origin Vite proxy → the WS upgrade carries the cookie.

Render

  • PitchCanvas.tsx — rAF canvas, DPR-crisp, ~30 fps.
  • homography.ts — a 4-corner GPS→pitch homography (unit-tested in homography.test.ts); geo.ts helpers.
  • render/interpolate.ts — honest bounded interpolation (ADR-0018): never fabricates a position past a cap; trail.ts draws motion trails.

Coaching & a11y

  • zones.ts — youth age-banded speed-zone colouring; thresholds come resolved from useSessionConfig.ts (single source of truth, ADR-0019).
  • A11yMirror.tsx — an accessible table mirror + ARIA; device-health ring from {event:'status'}.
  • useWakeLock.ts, useReducedMotion.ts, ErrorBoundary.tsx, explicit failure states.

Replay source

  • useHistory.ts → authed GET /sessions/:id/history (aggregate + heatmap default, raw paged).
  • Read off the live loop; same renderer as Live (ReviewView.tsx swaps the source).

Tactical timeline

  • useEvents.ts → GET /sessions/:id/events (Track A).
  • EventTimeline.tsx renders the team-shape series + heuristic phases (high-tempo / transition / stoppage), honestly labelled.

Identity, render-only

  • useRoster.ts → authed GET /sessions/:id/roster; names resolved client-side at render ONLY.
  • A name never enters the telemetry store, the DB, logs, metrics, or client persistence (ADR-0016).
  • Login.tsx + useAuth.ts (named login; /auth/login|logout|me).

Šta sistem prati — po igraču i po timu

Sve su pošteno označene procene izvedene iz kretanja (nikad „ground truth"). radi sad (v1) = automatski iz linka · treba kalibracija = kod gotov + testiran (100 testova), ali traži da se jednom obeleži teren (v2) · deli s GPS = isti rečnik kao GPS sistem. Golmani su izuzeti iz oblika tima i poseda.

PO IGRAČU
  • Stabilan ID + pripadnost timu (0/1) kroz ceo klip radi sad (v1)
  • Pozicija i putanja na terenu — pitch_xy u cm, posle homografije treba kalibracija
  • Pređeno rastojanje (m) — donja granica: filtriran šum + izglađeno + sample-fps takt; igrač koji stoji ≈ 0 m treba kalibracija
  • Maksimalna brzina (m/s) — održan vrh ≥0,3 s (nikad jedan kadar); nemogući skokovi odsečeni i izbrojani treba kalibracija
  • Kvalitet praćenja — broj odsečenih „outlier" segmenata po igraču treba kalibracija
  • Brzinske zone Z1–Z5 (hod→kas→trk→HSR→sprint) + sprint i accel/decel efforts deli s GPS
PO TIMU
  • Posed lopte % — najbliži igrač u 3 m; samo bliska/centralna zona, daleka strana „ne računa se" treba kalibracija
  • ball_known_fraction — koliko je lopta stvarno viđena; <0,7 ⇒ posed je „niska pouzdanost", ne čvrst broj v2
  • Oblik tima kroz vreme — centroid, površina konveksnog omotača (m²), rasprostranjenost (m), kompaktnost treba kalibracija
  • Promene poseda (heuristika, opciono) — najslabija metrika, jasno tako označena treba kalibracija
  • Radar odozgo — pozicije oba tima + lopta na terenu 12000×7000 cm v2
  • Faze igre — visok tempo / tranzicija / prekid (deli rečnik sa GPS Track A) deli s GPS

Sve izlazi kao stabilan stats.json (šema §7.4) + jednoekranski summary.txt; svaki broj nosi „provenance" zastavice (heuristika · sirovi/stitched ID · uređaj). v1 (igrači + timovi + anotirani snimak) radi automatski iz linka; mere koje traže poziciju na terenu uključuju se kad se doda kalibracija terena (v2).

the contract that flows

WorldState — one frame's worth of truth

footballcv/types.py. Every stage from track onward reads and returns this. Structurally the CV cousin of Telemetry.

# types.py WorldState(frame_idx, frame_ts, track_id_space, players[], ball) PlayerObs(track_id, cls, team, image_bbox, pitch_xy, confidence) BallObs(image_xy, pitch_xy, confidence, interpolated)

cls ∈ player/goalkeeper/referee · team ∈ 0/1/None · pitch_xy is cm on a 12000×7000 pitch (None pre-homography).

phased build

v1 → v2 → v3 (all built & green)

v1 — players & teams. decode → detect(players) → BoT-SORT track → SigLIP team split → annotated video. run_v1(), fully mock-integration-tested + verified runnable end-to-end on CPU.

v2 — ball + homography + radar. dedicated ball pass (2×2 tiling), self-grading homography (held-out validated), honest ball post-process (≤0.5 s capped interpolation + ball_known_fraction), top-down radar.mp4. run_v2().

v3 — analytics. possession % (near-centre only, far-side "not_computed"), per-player distance/speed (noise-floored lower bound, sustained ≥0.3 s peak), possession-changes (heuristic, opt-in), team-shape → stats.json + summary.txt. run_v3().

v4 — GoPro 360 de-warp. Not built. An ffmpeg v360 pre-pass that flattens a 360 clip to a fixed virtual camera the v1–v3 stack consumes unchanged.

Docker-only

Three images, nothing on the host

  • cpu — python:3.11-slim, light deps, the test suite. Runs anywhere (incl. the Mac). docker compose run --rm test.
  • gpu — pytorch+CUDA base, the real pipeline on an RTX 3060, behind the gpu compose profile (never built on a non-NVIDIA host).
  • cpurun — slim + CPU torch + ultralytics: the Mac real-inference image, used to smoke-test the pipeline without a GPU.

fetch_models.py is the one setup-only network module: gdown public weights (no API key) + a SigLIP pre-fetch into a persisted HF_HOME.

determinism & honesty

The model is allowed to be unsure

  • Determinism = team-id anchoring stability (smaller mean image-x ⇒ team 0) + fixed seeds — NOT bit-equality (CUDA/BoT-SORT aren't bit-reproducible).
  • Ball honesty: interpolation is capped at 0.5 s, flagged interpolated=True; over-cap gaps stay empty; ball_known_fraction is reported.
  • Distance is a noise-floored lower bound; far-side possession reads not_computed rather than a biased number.
  • Weights are SHA-pinned in models/MANIFEST.json, verified on load.
what the CPU smoke caught

Five real runtime gaps — found before the 3060 ever ran

Unit tests mock the model boundary, so they couldn't catch these; a real CPU run did. All five would otherwise have hit the owner's GPU run.

  • SigLIP team-classifier was never pre-fetched, and the offline guards block its runtime download → fetch_models.py now caches it into a persisted HF_HOME.
  • SigLIP's AutoProcessor needed sentencepiece → switched to image-only AutoImageProcessor (we never tokenise text).
  • hevc_nvenc was hardcoded → a libx264 fallback chosen by device (no NVENC without an NVIDIA GPU).
  • BoT-SORT needs lap → added lapx.
  • run_v1 passed the tracker-config dict where ultralytics wanted the yaml path → fixed.
The load-bearing constraint

Children's location & imagery — the #1 protected asset

The name firewall

Location stores stay pseudonymous: only a playerId ever enters a telemetry frame, a DB row, a log line, or a Prometheus label. A child's name is resolved only client-side at render, from an authenticated per-session roster — never persisted, never bundled (ADR-0010, ADR-0016).

Real-time side

  • 30-day local retention + erasure; cloud holds aggregates only (ADR-0010).
  • Devices never face the internet; one isolated WPA2 AP on match day (ADR-0006/0013).
  • Per-device MQTT identity + topic ACLs (ADR-0007).
  • Track A events are team-aggregate — no playerId at all.

CV side

  • Public adult/pro footage ONLY, every phase. No youth footage anywhere.
  • The pipeline makes no run-time network calls; offline guards set first.
  • models/, samples/, out/, calibration are gitignored — a firewall against committing footage/weights.
  • No player name ever enters stats.json (numeric ids + team only).

The deferred gate

  • Filming a real youth match is a separate, later gate: DPIA, consent, retention — owned by a future ADR.
  • The CV project inherits but does NOT discharge ADR-0020 §6's child-video DPIA.
  • Prototype on public video; the real-youth-footage decision stays parked.
